## 1. 三条主线

```
浏览器 public/app.js
   │  WebSocket /ws（JSON）
   ▼
server/index.js ──► server/rooms.js ──► src/engine/game.js
   │                                      │
   │ 静态文件                                ├─ actions.js / map.js / rng.js
   │ /  → public/                          ├─ shared/ring.js（前后端共用）
   │ /shared/ → shared/                    └─ aiRuntime.js ──► ai/models/*.js
   │                                                          └─ ai/lib/*.js
   └─ 对局结束：gameover + 完整 replay 记录 → 浏览器 history.js（IndexedDB）
```

- **规则只信服务端**：客户端拿到的 `view` 已经按玩家过滤，不能把规则判断搬到前端。
- **AI 只拿自己的视角**：`buildAIContext()` 刻意不提供其他玩家位置。
- **回放是上帝视角**：完整攻击结果、所有位置只进 `getReplayRecord()`，不进玩家 `view`。

## 5. 不能破坏的约束

1. **信息隔离**：非观战者的 `getView()` 只返回自己的 `position`；`buildAIContext()` 的 `players` 不含位置。任何“方便调试”的全量位置下发都不允许。
2. **攻击结果不回传**：玩家/AI 只知道自己开了枪、目标弧长；命中/空枪/被挡/互射结果只进回放。
3. **结算顺序固定**：藏 → 观 → 溜 → 攻 → 死亡；原上藏是空挂，柱上藏才隐身。
4. **阶段机**：`lobby → selecting → resolved → selecting / over`；`over` 后不再开新回合。
5. **超时与 AI**：人类超时按藏；AI 与人类同时推理；人类全部提交后等 AI 完成再结算。
6. **AI-only**：没有存活人类时用 `autoResolveAIOnly()` 跑到结束，不能卡在 `selecting`。
7. **`shared/ring.js` 必须同构**：Node 和浏览器都能直接 import；不能出现 `window`、`fs`、`process`。
8. **浏览器用绝对路径 import**：`/board.js`、`/shared/ring.js`；服务端把 `/shared/` 映射到 `shared/`，其余映射到 `public/`。
9. **发布包不包含测试/训练/工具**：见 §7 白名单。
10. **规则改动必须同时动测试和规则书**：`test/engine.test.js` + `规则书.md`（或明确只改实现不改规则，并写进 RELEASE 说明）。

## 7. 发布流程（当前是手工打包）

### 7.1 包内白名单

**完整版** `黑暗森林-<版本>.zip`：

- 根：`.gitignore`、`README.md`、`README.en.md`、`RELEASE-<版本>.md`、`RELEASE-<版本>.en.md`、`AI-BRIDGE.md`、`AI-BRIDGE.en.md`、`OPL联机说明.md`、`OPL联机说明.en.md`、`游戏介绍.md`、`游戏介绍.en.md`、`玩法与策略说明.md`、`玩法与策略说明.en.md`、`规则书.md`、`规则书.en.md`
- 启动：`start.bat`、`run-hidden.vbs`、`open-browser.vbs`、`launcher.mjs`、`ai-bridge.mjs`、`start-ai-bridge.bat`、`install-ai-bridge.bat`
- 依赖：`package.json`、`package-lock.json`、`node_modules/ws/**`
- 运行时：`runtime/node.exe`、`runtime/README.txt`
- 代码：`server/**`、`src/engine/**`、`shared/**`、`public/**`（含 `public/audio/**`）
- AI：`ai/models/**`、`ai/lib/**`、`ai/external/_template/model.json`、`ai/README.md`、`ai/README.en.md`、`ai/EXTERNAL-MODELS.md`、`ai/EXTERNAL-MODELS.en.md`、`ai/gpu.config.json`

**Lite 版** `黑暗森林-<版本>-lite.zip`：完整版去掉 `public/audio/**`，其余完全相同。

**明确不进包**：

`test/`、`tools/`、`ai/sim/`、`ai/train/`、`设计笔记.md`、`GPU-VS-AI2.md`、`TRAINING-ITERATION-1.md`、`screenshots/`、`dist/`、`release/`、`logs/`、`docs/`、`AGENTS.md`、`AGENTS.en.md`、`node_modules` 里除 `ws` 以外的内容。

> 注意：`docs/` 和 `AGENTS.md` / `AGENTS.en.md` 是维护资料，不随玩家包发布；如果希望玩家看到维护指南，需要单独决定。

### 7.2 打包步骤

1. 跑 `npm run verify`；
2. 按 §8 升版本号、写 `RELEASE-<版本>.md`、补 `设计笔记.md`；
3. 新建临时目录，按 7.1 白名单复制（不要直接压整个仓库，`dist/` 有 1.4 GB、训练数据约 390 MB）；
4. `Compress-Archive` 生成完整版；复制一份后删除 `public/audio/` 生成 Lite 版；
5. 用 SHA256 生成校验文件，格式为「大写哈希 + 两个空格 + 文件名」：

```powershell
Get-FileHash 'dist\黑暗森林-<版本>.zip' -Algorithm SHA256 | ForEach-Object { "$($_.Hash)  $(Split-Path $_.Path -Leaf)" } | Set-Content 'dist\SHA256-黑暗森林-<版本>.txt'
```

6. 解压 zip 到干净目录，双击 `start.bat`，确认 `/api/health` 和页面正常。

### 7.3 发布检查

- [ ] `npm run verify` 全绿
- [ ] 包内没有 `test/`、`tools/`、`ai/sim/`、`ai/train/`、`docs/`
- [ ] 完整版和 Lite 版都包含 `*.en.md` 英文文档；Lite 版仍然不含音频
- [ ] 完整版有 `public/audio/playlists/long-night-dam/`，Lite 版没有
- [ ] `runtime/node.exe` 存在，`node_modules/ws` 完整
- [ ] 解压后双击 `start.bat` 能打开 `http://localhost:3001`
- [ ] `RELEASE`、`README`、`package.json`、启动日志里的版本一致
- [ ] 两个 zip 的 SHA256 文件已生成

## 10. 已知维护债 / 下一步

- **没有 git 仓库**：当前目录不是 git repo，改动前只能靠 `dist/` 和备份。建议后续 `git init`，并把 `dist/`、`release/`、`runtime/`、`ai/train/data/`、`ai/train/checkpoints/*.pt`、`public/audio/**/*.wav` 加进 `.gitignore`。
- **发布打包手工**：没有 `build-release` 脚本，白名单靠人记；容易漏 `node_modules/ws` 或误带训练数据。可做 `tools/build-release.mjs`。
- **`public/app.js` 是单体**：已用分区标记降低检索成本，但仍是 2800 行；后续可按“设置/房间/回放/对局/行动”拆模块。
- **UI 没有自动化测试**：只有 engine/AI 单测；UI 靠 `?auto=1` 冒烟和截图。
- **`release/` 为空目录**：历史遗留，实际产物在 `dist/`。
- **`dist/` 体积 1.4 GB**：旧版本 zip 累积；保留最近 2–3 个版本即可，旧包可归档到仓库外。
- **`logs/server-errors.log` 多为端口占用**：`start.bat` 在 3001 被占用时会重试 3 次；排查先看端口，不要误判为代码崩溃。
- **训练数据/权重很大**：`ai/train/data/*.jsonl` 约 390 MB；不要在普通编辑器里打开，用 `Get-Content -TotalCount` 或流式脚本。

## 11. 故障排查速查

| 现象 | 先查 |
|---|---|
| 启动后立刻退出，日志 `EADDRINUSE` | 3001 被占用；换 `PORT=3010` 或关掉旧进程 |
| 页面能开但没 AI | `ai/models/` 是否为空；`/api/health` 的 `aiModels` |
| 房间内“开始对局”灰 | 人数 < 2、AI 模型无效、或非房主 |
| 联机加入不了 | 房主防火墙 3001；OPL 映射的本机端口；房间码大小写 |
| 回放没有记录 | 对局是否正常结束；浏览器是否清过站点数据；是否在结束前掉线 |
| Bridge 连不上 | 3210–3218 是否被占用；`round_ack` 是否回复；是否只监听 `127.0.0.1` |
| AI 卡住不结算 | 看服务端日志 `[ai]`；AI 模型是否抛错/超时；`prepareAIActions` 是否完成 |
| 修改后页面旧 | 服务端 `cache-control: no-cache`；浏览器硬刷新；确认改的是 `public/` 而不是 `dist/` 里的旧包 |

## 12. 改动流程（建议）

1. 在 §3 路由表找到分区；只打开对应文件；
2. 先读该分区的入口函数和相邻测试；
3. 改代码；
4. 跑最小验证，再跑 `npm run verify`；
5. 行为/规则/协议变了 → 按 §9 同步文档；
6. 版本发布 → 按 §7、§8；
7. 如果发现路由表没有覆盖的新区域，**先更新本文和 `AGENTS.md`**，再继续。
