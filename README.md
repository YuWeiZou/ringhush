# 黑暗森林（Dark Forest）

> [English](./README.en.md) | 中文
>
> 游戏界面本身保持中文，不设中英切换；需要时使用浏览器自带翻译。

一个环形地图、同时行动、隐藏信息的在线桌游。**Release 2.6.1a19** 自带 Windows 运行时：房主双击 `start.bat` 即可启动并自动打开浏览器，不需要安装 Node.js/npm；其他玩家只用浏览器打开房主的局域网地址。每局结束后，每个玩家的浏览器都会保存一份完整的上帝视角回放。

完整介绍见 [游戏介绍.md](./游戏介绍.md)；完整规则见 [规则书.md](./规则书.md)（v1.0.0）；玩法与基本策略见 [玩法与策略说明.md](./玩法与策略说明.md)；AI 插件说明见 [ai/README.md](./ai/README.md)；设计分析见 [设计笔记.md](./设计笔记.md)；OPL/OpenP2P 联机见 [OPL联机说明.md](./OPL联机说明.md)；Release 说明见 [RELEASE-2.6.1a19.md](./RELEASE-2.6.1a19.md)。

## 快速开始（Release 包）

1. 解压整个 `黑暗森林-2.6.1a19` 文件夹；
2. 双击 `start.bat`；
3. 浏览器会自动打开 `http://localhost:3001`。

不需要安装 Node.js、npm 或任何插件。`start.bat` 使用包内自带的 `runtime\node.exe`。默认隐藏运行；首次窗口会等服务端健康检查通过后打开浏览器，然后自动关闭。需要看启动日志时运行 `start.bat --console`。

开发环境（已安装 Node.js）仍可使用：

    npm install
    npm start

浏览器打开 `http://localhost:3001`。

## 局域网联机

本 Release 只整理局域网联机，内网穿透/公网映射暂不配置。

房主运行服务端，其他人打开 `http://{房主IP}:3001`，用房间码加入。房间最多 **8 人（人类 + AI）**，不预选总人数；人类陆续加入，房主可在房间里添加/删除 AI 座位。

### 局域网联机步骤

1. 房主双击 `start.bat`，浏览器会自动打开本机页面；启动日志默认不显示，需要时用 `start.bat --console`；
2. 其他玩家在同一局域网打开这个 `LAN` 地址，不需要安装任何东西；
3. 房主点“局域网联机 → 创建房间”，把 4 位房间码发给朋友；
4. 朋友点“局域网联机 → 填昵称/房间码 → 加入房间”；
5. 房主添加 AI、选型号/随机、设回合计时，人数达到 2 后点“开始对局”。

“房主”是创建房间的玩家；服务端跑在主机上。其他玩家必须与主机在同一局域网内。

## 怎么玩

1. 本地对局：点“开始本地对局”进入房间；联机：点“局域网联机”，创建房间或用房间码加入。
2. 房主在房间里添加/删除 AI，给每个 AI 选型号或“随机”；设置每回合操作时间（20 秒–3 分钟，默认 60 秒）。
3. 人数 = 人类 + AI，达到 2–8 人即可开始，不要求满人；开始后 AI 型号和计时锁定。
4. 每回合从 **藏 / 观 / 攻 / 溜** 中选一个；藏只能在柱上生效，原上藏是空挂。
5. 结算顺序：**藏 → 观 → 溜 → 攻 → 死亡**；超时按藏处理。
6. 第 2 回合首次预告，第 4 回合首次轰炸；之后按存活人数：大于半数间隔 3 回合、单目标；小于等于半数间隔 2 回合、单目标；小于等于四分之一间隔 3 回合、一次预告两个目标并同时爆炸。
7. 结算后所有存活人类点“继续”才进下一回合；结果阶段 10 秒自动继续。活到最后获胜；同一回合全灭平局。
8. 对局中非房主断线：本回合按【藏】处理，立即死亡，公开广播“因断线死亡”，尸体正常记录；房主断线仍会关闭房间。

对局中没有聊天或交流通道；AI 只能使用自己的私密信息。

游戏内点“规则”可以看速览。

### 操作

- **观**：选方向 + 长度；原上整圈，柱上最多半圈。
- **攻**：先点“攻”，再点地图上的段选目标；方向决定攻击弧长。枪声不会公开精确段，其他玩家只会得到“左/右”以及左右分别响了几次。
- **溜**：从可用落点里选；原上可能可以走 2 段，或从原侧直穿废墟。
- **情报**：点击情报条目可以只看那一回合；地图下方“情报回溯”时间条可以回到“全部”。
- **情报可视化**：观测到有人的段会留下红点 + `R回合` 标签；半区枪声显示为地图外圈的蓝色光弧，情报面板显示左右两侧的开枪次数。历史信息不会消失，可用时间条回溯。
- 结算弹窗可以“先看地图”或“继续下一回合”。

## 辅助设置

主菜单、准备房间、对局内、回放里都有“辅助设置”，只影响本机：

- **界面字号**：100% / 115% / 130% / 145%；
- **高对比度**：加亮文字、边框和状态色；
- **棋盘大标签**：放大段号、地形字样、玩家/尸体标签；
- **减少动画**：关闭淡入、脉冲和过渡；
- **键盘操作**：对局内 `1` 藏、`2` 观、`3` 攻、`4` 溜，`Enter` 提交；
- 设置保存在本机浏览器，刷新后仍生效。

## 历史对局与回放

- 退场玩家自动进入**上帝视角**：能看到所有玩家位置、地形和公开事件，继续看下去；
- 只剩 AI 时服务端直接模拟到结束，保存完整记录；对局结束直接回到房间，不自动开始下一局；
- 对局正常结束（分出胜负/平局）时，服务端会把**完整上帝视角记录**发给仍连接的每个玩家；
- 每个玩家的浏览器用 IndexedDB 保存在**自己电脑上**，不是只存在房主机器；
- 主菜单 →“历史对局”可以查看本机记录；
- 每回合结束自动打开“回合复盘”结算面板；
- 联机房间里有“历史对局”按钮，历史列表直接展开在房间下方，不遮挡房间；
- 回放按**回合滑块**手动拖动，支持上一回合/下一回合，以及“回合开始 / 回合结束”切换；
- 显示所有玩家的真实位置、行动、移动/攻击连线、死亡、轰炸/废墟、公开事件和每个人的私密事件；
- 回放中藏身玩家 token 白边；观测玩家在最外圈显示对应颜色弧线，重叠时同心不同半径；
- 删除只删除本机这条记录，不影响其他玩家，也不会影响服务器；
- 浏览器清空站点数据/无痕模式会清掉本机记录。
- 尸体标记：存活玩家只看到**自己当前段**的尸体；知道公开死亡名单，但不知道别处尸体位置，也不知道真实死亡回合，只知道“自己第几回合发现”。再次来到同段会更新新尸体。尸体不阻挡移动/观测/攻击。回放为上帝视角，显示全部尸体、真实死亡回合和姓名；死者不再作为独立 token 叠在一起，而是按段聚合。

## 启动/连接恢复

- 服务端异常退出时 `start.bat` 自动重启，最多 3 次；
- 异常写入 `logs\server-errors.log`；
- 浏览器全部关闭后，服务端在 5 秒宽限期后自动退出；刷新页面会在宽限期内重连；
- 浏览器断线会尝试重连；连续失败显示“连接已断开”和“刷新重连”；
- 页面脚本异常显示“页面出现异常”和刷新按钮，避免只剩黑屏；
- 断线只恢复到主菜单/大厅，不恢复进行中的房间。

## 外部 AI Bridge（v2.1.0）

- 每个玩家在自己电脑上运行一个本机 Bridge；
- 控制口 `127.0.0.1:3210`，模型口 `3211–3218`；
- 只转发该玩家自己的视角，不出局域网；
- 设置里启用“外部 AI 通道”，房间内点“打开本机 Bridge”；
- 首次客机运行 `install-ai-bridge.bat` 注册 `dfbridge://`；
- 手动确认 / 自动提交，自动提交有 1.5 秒人类覆盖窗；

## OPL / OpenP2P 联机

游戏只用一个 TCP 端口，默认 **3001**；房间码是逻辑房间，不需要随机端口。OPL 连接不上时，优先检查 OPL 隧道是否把 **3001** 映射到加入方本机端口。

- 旧配置里的 `37520` 是 Minecraft/旧预设端口，不是本游戏端口；
- OPL 面板里的“本机/本地端口”才是浏览器要访问的端口，打开 `http://127.0.0.1:{本机端口}`；
- 不要拿 OPL 的 UID 当连接码，使用 OPL 生成的连接码；
- 也可以用 EasyTier 组网，然后打开 `http://{房主虚拟IP}:3001`。

详细步骤见 [OPL联机说明.md](./OPL联机说明.md)。

## 当前实现范围

- 地图：`S = 3n`（偶数则 `3n+1`），柱 `floor(1.5n)`，随机初始位置，地图结构公开。
- 行动：藏/观/攻/溜；半区暴露、枪声左/右次数、互射弧长、溜杀/观反杀、拥挤按移动距离、1 点血、轰炸/废墟、废墟原侧直穿、观/攻不被废墟阻挡、胜利/平局。
- 信息隔离：服务端按玩家过滤 `view`，客户端只知道自己的位置、观测结果和半区线索，不会收到其他玩家的位置。
- AI：内置 JS 模型在 `ai/models/`，外部 JSON 条件模型在 `ai/external/`；当前为 AI 2.3.3（适应者/猎手/潜行者/灰烬/守夜人 + 本地显卡适配器）。1v1 锁定无移动目标会强制长弧攻击，但自己踩在可规避轰炸区时优先溜；残局会用最近枪声半区修正旧红点。AI 只拿自己的 `view`，看不到其他玩家位置。
- 房间：局域网创建/加入、房间码、人类昵称、房主动态加/减 AI、AI 型号或随机、20–180 秒计时、存活人类全部继续 + 10 秒自动继续。
- 超时：该回合未提交的人类自动【藏】；原上藏为空挂，不隐身/不挡枪。AI 与人类同时开始推理，人类全部提交后等 AI 完成再结算。
- 回放：正常结束时每名在线玩家本机保存完整记录；主菜单历史列表、删除、按回合滑块复盘、回合开始/结束切换。
- 观战：退场玩家自动获得上帝视角；只剩 AI 时直接模拟到结束，记录存档后回到房间，不自动下一局。
- 开火反馈：玩家和 AI 只知道自己的目标与弧长，不反馈空枪/被挡/命中/互射压制；完整攻击结果只进入上帝视角回放。
- 辅助设置：字号、高对比度、棋盘大标签、减少动画、键盘 1–4/Enter，本机保存。

## AI 逻辑文件夹

AI 逻辑独立在 `ai/`：

    ai/
      models/          内置 AI 型号（*.js）
      external/        外部 JSON 条件模型（房主提供）
      lib/             共用推理工具
      sim/             自对弈模拟
      gpu.config.json  本地显卡模型配置

- **空文件夹 = 不允许添加 AI**：`ai/models/` 为空或不存在时，服务端仍启动，但房间内会显示“缺少 AI 模型”，不能开始带 AI 的对局。
- **安装内置模型**：把 JS 模型放进 `ai/models/`，重启服务端。
- **安装外部模型**：把 `model.json` 放进 `ai/external/{id}/`，重启服务端；只支持 JSON，不能执行任意代码。完整格式见 [ai/EXTERNAL-MODELS.md](./ai/EXTERNAL-MODELS.md)。
- **选择**：房间内、正式对局开始前，房主可逐个 AI 座位切换型号；开始后锁定。
- **模型只能拿到自己的信息**：`ctx.players` 没有位置；位置只能来自自己的观测红点、枪声和公开信息，开火结果不反馈。
- **本地显卡模型**：`gpu` 型号（2.3.0）通过本机 OpenAI 兼容服务（Ollama / llama.cpp / vLLM）在 7900 XTX 上推理；Node 只发压缩局面和收 JSON 行动，不把推理塞进游戏进程。配置见 [ai/README.md](./ai/README.md)。
- **本机已验证**：Ollama 0.40.6 + `qwen2.5:3b`，`ollama ps` 显示 100% GPU；预检 `npm run gpu:check`。
- **随机池**：`basic`（守夜人）只会藏/整圈观察，已设为 `randomPool: false`，不进随机池，但可手动选。`gpu` 本地模型版本为 2.3.0。
- **本地模型胜率**：`qwen2.5:3b` 对 `adaptive` 50 局 15:31（4 平，32.6% 不含平局），但 80.7% 动作回退了猎手；纯模型组 20 局仅 5%。见 [GPU-VS-AI2.md](./GPU-VS-AI2.md)。
- **训练基线**：`ai/train/` 迭代 1 使用 92,521 条决策、3 个 seed；最佳验证动作准确率 67.6%。见 [ai/train/README.md](./ai/train/README.md)。
- **学徒模型**：`apex-safe` 是 4 人局守门版，学生权重 JSON；4 人局 500 局座位胜率 27.2% vs adaptive 20.0%，2/8 人局回退 adaptive。见 [ai/train/APEX-REPORT.md](./ai/train/APEX-REPORT.md)。
- **模拟**：

    npm run sim -- --games=500 --players=2,4,8

结果写入 `ai/sim/results.json`。当前默认 `adaptive`（适应者）在多人局更稳，2 人残局自动复用猎手逻辑。

## 联机接口（已预留）

WebSocket：`/ws`，消息 JSON。

客户端 -> 服务端：

    { "type": "local", "name": "你" }
    { "type": "createRoom", "name": "房主" }
    { "type": "joinRoom", "roomId": "ABCD", "name": "玩家" }
    { "type": "addAI" }
    { "type": "removeAI", "playerId": 100 }
    { "type": "setAI", "playerId": 100, "modelId": "hunter" }
    { "type": "setTimer", "seconds": 60 }
    { "type": "startRoom" }
    { "type": "action", "action": { "type": "attack", "target": 4, "dir": 1 } }
    { "type": "continue" }
    { "type": "restart" }
    { "type": "menu" }

服务端 -> 客户端：

    { "type": "lobby", "roomId": "ABCD", "playerId": 0, "hostId": 0, "started": false, "maxTotal": 8, "total": 3, "turnSeconds": 60, "models": [], "humans": [], "aiSlots": [], "canAddAI": true, "canStart": true }
    { "type": "state", "view": { "...": "...", "room": { "deadline": 0, "resultDeadline": 0, "ready": [] } } }
    { "type": "gameover", "view": { "...": "..." }, "winnerId": 2 }
    { "type": "error", "message": "..." }

- `local` / `createRoom` / `joinRoom` 先进入房间，不会自动开始；房主 `startRoom` 才开始。
- 房间最多 8 人（人类 + AI）；`addAI` / `removeAI` / `setAI` / `setTimer` 只能由房主在开始前调用；AI 型号可选具体 id 或 `random`。
- `turnSeconds` 为 20–180，默认 60；超时按藏。`continue` 由存活人类点击，全部就绪或 10 秒后进入下一回合。
- 每个客户端只会收到自己的 `view`，其中不包含其他玩家的位置。
- 第一版不做局内断线重连/托管、邀请链接；有退场观战和本机回放。

## 开发提示

- `npm run dev`：`node --watch` 自动重启服务端。
- `?auto=1&players=4`：打开页面后自动开始本地局，方便截图/冒烟测试。
- `?debug=1`：暴露 `window.__DF_DEBUG__`，可强制渲染结算 UI（开发用）。
- `PORT=3010 npm start`：换端口。
- 规则书 v1.0.0 的轰炸参数：首次固定第 2 回合预告第 4 回合；之后按存活人数切换 3 回合单区 / 2 回合单区 / 3 回合双区；全段目标池、无差别、目标段上的人死亡、废墟不可进入、观/攻不被阻挡、回合开始结算。

## 已知限制

- 房主离开会关闭房间；非房主在对局中离开按【藏】+死亡+公开广播处理；不做局内断线重连/托管。
- AI 是规则型/外部模型混合：默认型号不保证最优，`basic` 只是基线。GPU 型号需要本机推理服务，且会受显存/延迟影响。
- 未做账号、匹配、重连、观战、音效、移动端专门适配。
- 回放只保存在各玩家浏览器本地；换电脑、清站点数据、无痕模式不会同步/保留。断线玩家在结束前掉线则没有这一局的本地回放。
- 回放按回合而不是按每个结算子步骤切片；本回合内的“藏→观→溜→攻→死亡”按侧栏事件顺序展示。
- 规则书里仍标“暂定”的轰炸参数（柱-柱硬墙、连续废墟、结算时机等）按当前默认实现。
